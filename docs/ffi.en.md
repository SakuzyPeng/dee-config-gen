# FFI Bridge (v1)

[中文](ffi.zh.md) | [User README](../README.en.md)

This document defines the C ABI v1 for `dee-config-gen` cross-language integration.

## Capability Scope

v1 exposes two stateless entrypoints:
- `dcg_validate_job`
- `dcg_generate_config`

`run` is intentionally out of scope for FFI v1. Host applications should execute runners themselves.

## ABI Versioning

- `dcg_abi_version()` currently returns `1`
- Within one ABI version:
  - status code numeric values are stable
  - struct field semantics are stable
- Breaking ABI changes require a new version

ABI break policy (v1):
- v1 is treated as a strictly frozen protocol
- if status code values, critical `#[repr(C)]` layout, or field offsets break, ABI version must be bumped
- `tests/ffi_abi_contract.rs` is a release-blocking gate

## Inputs and Defaults

- Input `job` is `DcgStringView { ptr, len }` and must be UTF-8 YAML/JSON text
- `options == NULL` uses defaults:
  - `template_override=None`
  - `allow_fixed_override=false`
  - `windows_drive='Y'`
  - `format=xml`
- `windows_drive=0` also falls back to `'Y'`

## Status Codes

- `DCG_STATUS_OK`
- `DCG_STATUS_INVALID_ARGUMENT`: null pointers, invalid enums, invalid drive, non-UTF8, etc.
- `DCG_STATUS_PARSE_ERROR`: failure in `parse_job_str`
- `DCG_STATUS_RESOLVE_ERROR`: failure in `resolve/validate`
- `DCG_STATUS_RENDER_ERROR`: failure in `render_config`
- `DCG_STATUS_INTERNAL_ERROR`: unexpected bridge-layer internal error
- `DCG_STATUS_PANIC`: Rust panic captured at the FFI boundary

Rules:
- branch on status codes, not message text
- treat message text as diagnostic logging only

## Memory Ownership

- All `DcgOwnedString` values in success outputs and errors are allocated by Rust
- Caller must release with:
  - `dcg_free_string`
  - `dcg_free_validate_output`
  - `dcg_free_generate_output`
  - `dcg_free_error`
- Free functions are safe on zero/empty values and can be called repeatedly

## Minimal C Example

```c
#include "dee_config_gen_ffi.h"
#include <stdio.h>
#include <string.h>

int main(void) {
  const char *job_text =
      "template_id: atmos_ec3_v1\n"
      "profile: standard\n"
      "job_mode: single\n"
      "encode_mode: streaming\n"
      "input:\n"
      "  storage_path: ./input\n"
      "  file_names: [testADM.wav]\n"
      "output:\n"
      "  storage_path: ./output\n"
      "  file_names: [output.ec3]\n"
      "misc:\n"
      "  temp_dir: ./tmp\n";

  DcgGenerateOutput out = {0};
  DcgError err = {0};
  DcgStatusCode code = dcg_generate_config(
      (DcgStringView){(const uint8_t *)job_text, strlen(job_text)},
      NULL,
      &out,
      &err);

  if (code != DCG_STATUS_OK) {
    fprintf(stderr, "generate failed: code=%u, msg=%.*s\n",
            (unsigned)code, (int)err.message.len, (const char *)err.message.ptr);
    dcg_free_error(&err);
    return 1;
  }

  printf("generated bytes=%zu\n", out.rendered_config.len);
  dcg_free_generate_output(&out);
  dcg_free_error(&err);
  return 0;
}
```

## Header

Distributed header:
- `include/dee_config_gen_ffi.h`

Header source of truth:
- generated by `cbindgen` from `src/ffi.rs` using `cbindgen.toml`

Regenerate:

```bash
cbindgen src/ffi.rs --config cbindgen.toml --output include/dee_config_gen_ffi.h
```

Check drift:

```bash
scripts/check_ffi_header.sh
```

## CMake Consumer Example

Path:
- `ffi/example_cmake`

Local smoke (macOS/Linux example):

```bash
cargo build --release
cmake -S ffi/example_cmake -B ffi/example_cmake/build \
  -DDCG_INCLUDE_DIR="$PWD/include" \
  -DDCG_LIBRARY="$PWD/target/release/libdee_config_gen.dylib"
cmake --build ffi/example_cmake/build --config Release
ctest --test-dir ffi/example_cmake/build --output-on-failure -C Release
```

CI status:
- GitHub Actions workflow `.github/workflows/ffi-bridge.yml` validates:
  - `cargo fmt --check`
  - `cargo test --lib`
  - `cargo test --test ffi_integration`
  - `cargo test --test ffi_abi_contract`
  - `cargo build --release`
  - header drift check via `cbindgen`
  - CMake consumer build and run on Linux/macOS/Windows
- GitHub Actions workflow `.github/workflows/ffi-release.yml` supports:
  - `workflow_dispatch` dry-run (build/package/verify, no publish)
  - `v*` tag release (3-platform dynamic library zips + `include/dee_config_gen_ffi.h` + `SHA256SUMS.txt`)

## Release and Verification

- Release trigger: push a `v*` tag (for example `v0.1.1`)
- Download: the corresponding GitHub Releases page
- Verify checksums:

```bash
sha256sum -c SHA256SUMS.txt
```
