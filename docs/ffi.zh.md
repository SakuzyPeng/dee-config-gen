# FFI 桥接（v1）

[用户首页](../README.md) | [English](ffi.en.md)

本文档描述 `dee-config-gen` 的 C ABI v1，用于跨语言调用校验与配置生成能力。

## 能力边界

v1 仅开放两条无状态接口：
- `dcg_validate_job`
- `dcg_generate_config`

不开放 `run` 的 FFI 封装；外部进程调用 runner 由宿主语言负责。

## ABI 版本策略

- `dcg_abi_version()` 当前返回 `1`
- 同一 ABI 版本内：
  - 错误码数值稳定
  - 结构体字段语义稳定
- ABI 升级时增加版本号，不在旧版本上做不兼容字段重排

## 输入与选项

- 输入 `job` 使用 `DcgStringView { ptr, len }`，必须是 UTF-8 YAML/JSON 文本
- `options == NULL` 时采用默认值：
  - `template_override=None`
  - `allow_fixed_override=false`
  - `windows_drive='Y'`
  - `format=xml`
- `windows_drive=0` 也按默认 `'Y'` 处理

## 错误码语义

- `DCG_STATUS_OK`
- `DCG_STATUS_INVALID_ARGUMENT`：空指针、非法枚举、非法盘符、非 UTF-8 等
- `DCG_STATUS_PARSE_ERROR`：`parse_job_str` 失败
- `DCG_STATUS_RESOLVE_ERROR`：`resolve/validate` 失败
- `DCG_STATUS_RENDER_ERROR`：`render_config` 失败
- `DCG_STATUS_INTERNAL_ERROR`：桥接层内部预期外错误
- `DCG_STATUS_PANIC`：Rust panic 被边界捕获

规则：
- 业务分支必须看错误码，不依赖错误文案
- 错误文案只用于日志与排障

## 内存所有权

- 成功输出和错误消息中的 `DcgOwnedString` 都由 Rust 分配
- 调用方必须调用对应释放函数：
  - `dcg_free_string`
  - `dcg_free_validate_output`
  - `dcg_free_generate_output`
  - `dcg_free_error`
- 释放函数对空对象安全、可重复调用

## 最小 C 示例

```c
#include "dee_config_gen_ffi.h"
#include <stdio.h>
#include <string.h>

int main(void) {
  const char *job_text =
      "template_id: atmos_ec3_v1\n"
      "profile: standard\n"
      "job_mode: single\n"
      "encode_mode: streaming\n"
      "input:\n"
      "  storage_path: ./input\n"
      "  file_names: [testADM.wav]\n"
      "output:\n"
      "  storage_path: ./output\n"
      "  file_names: [output.ec3]\n"
      "misc:\n"
      "  temp_dir: ./tmp\n";

  DcgGenerateOutput out = {0};
  DcgError err = {0};
  DcgStatusCode code = dcg_generate_config(
      (DcgStringView){(const uint8_t *)job_text, strlen(job_text)},
      NULL,
      &out,
      &err);

  if (code != DCG_STATUS_OK) {
    fprintf(stderr, "generate failed: code=%u, msg=%.*s\n",
            (unsigned)code, (int)err.message.len, (const char *)err.message.ptr);
    dcg_free_error(&err);
    return 1;
  }

  printf("generated bytes=%zu\n", out.rendered_config.len);
  dcg_free_generate_output(&out);
  dcg_free_error(&err);
  return 0;
}
```

## 头文件

可分发头文件位于：
- `include/dee_config_gen_ffi.h`

头文件真相源：
- 使用 `cbindgen` 基于 `src/ffi.rs` 和 `cbindgen.toml` 生成

重新生成：

```bash
cbindgen src/ffi.rs --config cbindgen.toml --output include/dee_config_gen_ffi.h
```

漂移检查：

```bash
scripts/check_ffi_header.sh
```

## CMake 消费示例

目录：
- `ffi/example_cmake`

本地冒烟（macOS/Linux 示例）：

```bash
cargo build --release
cmake -S ffi/example_cmake -B ffi/example_cmake/build \
  -DDCG_INCLUDE_DIR="$PWD/include" \
  -DDCG_LIBRARY="$PWD/target/release/libdee_config_gen.dylib"
cmake --build ffi/example_cmake/build --config Release
ctest --test-dir ffi/example_cmake/build --output-on-failure -C Release
```

CI 状态：
- GitHub Actions 工作流 `.github/workflows/ffi-bridge.yml` 会在 Linux/macOS/Windows 上自动验证：
  - `cargo fmt --check`
  - `cargo test --lib`
  - `cargo test --test ffi_integration`
  - `cargo build --release`
  - `cbindgen` 头文件一致性检查
  - CMake 消费示例构建与运行
