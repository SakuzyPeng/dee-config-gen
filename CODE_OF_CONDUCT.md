# Code of Conduct

This project is maintained as a collaborative engineering space. We want issues, pull requests, and reviews to stay useful, respectful, and safe for contributors with different backgrounds and experience levels.

## Expected Behavior

- Be respectful, patient, and specific.
- Assume good intent while still being honest about technical risks.
- Keep feedback focused on code, behavior, evidence, and user impact.
- Help others reproduce problems instead of gatekeeping access to context.
- Respect license and redistribution boundaries for proprietary runtimes, fixtures, and documents.

## Unacceptable Behavior

- Harassment, intimidation, threats, or personal attacks
- Discriminatory or hateful language
- Doxxing or sharing private information without consent
- Repeatedly derailing technical threads after maintainers ask to refocus
- Posting proprietary assets, leaked documents, secrets, or private customer data without permission

## Scope

This code of conduct applies to:
- GitHub issues, pull requests, and code review threads
- repository documentation and examples
- other project spaces where people represent this repository

## Enforcement

Maintainers may take any action needed to protect the project and its contributors, including:
- editing, hiding, or removing content
- closing or locking threads
- rejecting contributions
- temporarily or permanently restricting participation

## Reporting

If you need maintainer help for a conduct issue and there is no private reporting path yet, open a minimal public issue titled `Maintainer contact requested` without personal or sensitive details. The goal of that issue should only be to establish a safer follow-up channel.

For platform-level abuse, also consider GitHub's built-in reporting tools.
